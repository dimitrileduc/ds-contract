### Ce que l'exécution a corrigé dans le plan ci-dessus (2026-08-05)

- **DW-001 (logo) — la prescription du point 2 est PÉRIMÉE, et pas d'un détail.** Elle dit « une prop enum + un token dont le CHEMIN contient la prop », en s'appuyant sur l'archive demo-51. Le relevé from-dump de 015 (T048) a mesuré la prémisse au lieu de l'hériter : **il n'existe pas deux tailles**. `ds.header` porte le logo à exactement 180×34 sur ses deux variantes, `ds.footer` à 180,0985×34 — la précision flottante des vecteurs du maître, pas une intention de design. L'owner a tranché pour la voie simple : deux tokens, zéro prop, zéro lift moteur. **Ne pas construire l'infrastructure décrite au point 2** ; reçu : `specs/014-…/proofs/recus/named-repair-DW-001.md`.
- **016 a grossi.** Aux défauts de source (DW-002, DW-003) s'ajoute désormais une tâche dimensionnante : **créer les variables Figma des 83 références minées par 015**. Sans elles, l'axe `variables canvas ⟷ tokens` — celui qui doit surveiller la géométrie côté maquette — reste acquitté : `parity/baseline.json` est passé de 7 à **89 acquittements**, tous pour cette raison (reçu `figma-tokens-behind-baseline.md`). 015 a fermé l'angle mort **côté code seulement** ; c'est 016 qui rebranche l'autre moitié.
- **Le reste de la spec 015 est fait comme prévu** : box-sizing corrigé à l'émetteur (+ 3 largeurs content-box réparées à la source : sav, footer, faq), DW-004/DW-005 convertis, les 2 dégradés hero portés comme littéraux nommés déclarés, préservation des correctifs 013 gardée par un contrôle (18/18).

Short version — four phases, each with a falsifiable exit criterion:

0. **Prove the model** — complete (July 2026): 51 contracts, two generated surfaces, three-way parity, 99/99 evals, measured governed-generation result.
1. **Harden the loop** — anatomy-level parity, fresh-file rebuild, automated visual regression.
2. **Brownfield adoption** — extract proposed contracts from *pre-existing* design + code libraries, reconcile, run diagnostic-only; public pilot on a real open-source pair.
3. **Spec candidacy** — separate format from implementation: normative spec draft, conformance kit, and a second independent implementation.
4. **Community & governance** — RFC process, engagement with DTCG / OpenUI / CEM, and a neutral multi-vendor home.
