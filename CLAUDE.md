# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

**Last updated**: 2026-08-06

## What this is

A proof-of-concept (and candidate reference implementation) for a vendor-neutral **component contract** spec. The load-bearing idea: a component's source of truth is neither the design file nor the code, but a small versioned **JSON contract** that *generates both* — a typed React library and a native Figma library — while a three-way differ continuously proves both still match the contracts.

Current state: the **Piqueray reconversion**. `contracts/` holds the governed Piqueray components (the Button first, more landing spec by spec) plus `contracts/icons.registry.json` (the governed icon set), on a single-brand, single-mode Piqueray token foundation. The 51-component demo system this started from was removed and archived (see Documentation map).

## The rules

- **Determinism — no AI in the conversion.** The contract→surface pipeline is pure functions, byte-pinned against golden manifests. AI may *assist* (propose a contract, help author an emitter) but is **never** in the generation path — "byte-identical across two runs" is the guarantee.
- **The claims rule — no capability claim without an eval behind it.** Order is always: fixture → eval → claim. Never add a capability sentence to README/docs before an adversarial check backs it in `npm run eval`. See `CONTRIBUTING.md`.
- **The source-cleanliness rule — clean the Figma BEFORE contracting it.** Step 0 of any component spec audits + cleans its Figma source (masters AND usage, every instance scanned by POSITION never by name) — THEN extract. Never model around a dirty source. **Corollary: for ANY discrepancy, first decide "is this from Figma or not?"** — a fixed-width master vs FILL usage, a raw hex vs a bound variable — before touching code. A Figma-source defect is fixed at the source, never worked around in code. *Stated in full, with the Button receipt, as constitution §VIII.*
- **The docs-first rule (§IX) — READ the docs BEFORE deriving.** `docs/` is the authoritative base; consult it via **auggie MCP** (`mcp__auggie__codebase-retrieval`, natural-language `information_request`) FIRST — before re-deriving a rule from the code, before a modeling decision, before answering a capability question. Key docs: `docs/handoff/` (13-file AI-to-AI onboarding, most authoritative), **`docs/FIGMA-CAPABILITY-MATRIX.md`** (every CSS↔Figma capability + the FIXED/HUG/FILL sizing model, what's CARRY-BOTH vs CARRY-CODE-ONLY vs a named limit), `docs/00-…-15-*.md`. *Stated in full as constitution §IX.*
  **Receipt (2026-08-03, and it is the reason this rule needs one).** An owner asked what happens to a designer's real photo when the canvas is regenerated — a pure capability question, answered by row 91 of the capability matrix. The agent spent an hour deriving instead: measuring, counting, reading emitters, and answering from inference. The matrix was never opened until the owner said to open it. The rule was in context the whole time. Two lessons, both structural: (1) **a capability / limit / "is it supported, carried, overwritten" question is a DOCS question — the matrix answers it, and its answer is authoritative over any inference from code**; (2) the failure was not ignorance of the repo but skipping one layer of it, which is why a global `UserPromptSubmit` hook (`~/.claude/hooks/docs-first-on-speckit.sh`) now lists the real `docs/` contents on every Spec-Kit command — a rule that is only written gets skipped, a rule that speaks every time does not. Corollary found the same day: the answer itself was missing from `docs/` (the image harvest/restore pass lived only in code comments and one eval header) — **when a doc cannot answer a fair question about a declared limit, the gap is the defect, not the asker.**
- **The before-capture rule (§X) — capture every affected target before any live Figma-canvas mutation starts, never just a pilot subset.** Once a raw copy is replaced on canvas, its pre-change state is gone for good. Before any replacement starts, capture the before-state for every target that will be touched — not a pilot page first — and verify each capture is non-empty and correctly sized before proceeding. *Stated in full as constitution §X.*
- **The prior-art rule — before proposing a workaround for a capability gap, go find how this codebase already solved it (owner rule, the review-card equal-width lesson, 2026-07-26).** Never conclude "the engine can't do X, here's a workaround" from first principles alone — check `docs/reference/demo-archive/` (the 51 pre-reconversion demo contracts, `INDEX.md` + `git show demo-51:<path>`) and `git log -S`/`git blame` on the relevant emitter/schema code FIRST. Receipt: spec 006 needed equal-width instances of a repeated child (`ds.review-card` inside `ds.google-reviews`'s `repeat`) — `layout.grow` doesn't apply to a contract's own root and wouldn't force equal widths even if it did (`flex: 1 1 auto` keeps a content-based basis, never `flex-basis: 0`). A fixed-width literal on the child's own root was proposed as a workaround *before* checking prior art. Only afterward did archive research confirm: `repeat` was never exercised by any of the 51 demo contracts (a real, first-of-its-kind gap — Piqueray's first `repeat`+`component` composite), but the ONE existing size-equality pattern in the archive (`ds.avatar-group`, stacked avatars) uses **exactly the same fixed-width-token-on-the-child's-own-root technique** — so the workaround was right, but arrived at by luck, not by evidence. Checking first turns "I think this is fine" into "this is the established pattern, here's the receipt" — cheaper than guessing and a lot cheaper than guessing wrong.
- **The geometry-rides-tokens rule — a contract's anatomy references TOKENS, never raw literals; a literal is invisible to the differ by design.** This is the load-bearing shape of the whole model, and it is easy to break without noticing. The three-way differ's axes are `code ⟷ contract`, `canvas ⟷ contract`, and **`canvas variables ⟷ tokens/`** (`docs/06-parity-loop.md`) — so geometry is watched *through the token axis*. A padding carried as `"89px"` sits on no axis at all: nothing proposes it, nothing flags it, and `npm run parity` stays green while the surfaces drift. The reference is unambiguous: the 52 archived demo-51 contracts (`docs/reference/demo-archive/`) carry **zero** `literals` — everything is `{space.gap.sm}`, `{size.card.width}`, `{border-width.100}`. And the Piqueray foundation states the doctrine in its own token file (`tokens/primitives.tokens.json`, `space.$description`): *"NOT Figma variables — Piqueray binds no spacing variables; **minted from-dump so anatomy references tokens, not literals**."* That is also why extraction looks thin: `core/propose-figma.ts` inverts the generator's rules over **variable bindings** (`paddingLeft==paddingRight → padding-inline`, `itemSpacing → gap`), so an unbound raw value is *reported*, not carried — and a source that binds nothing yields a contract that carries nothing. **Receipt (2026-07-30, spec 013, `footer`):** the audit found 74 Figma facts the contracts did not carry; the fix was written as `"padding-left": "89px"` and `"padding-top": "128px"` **while `{space.89}` and `{space.128}` already existed, minted for exactly this**. Pixels went 96.91 % → 1.04 % and the shape got further from the reference — a green render on an invisible fact. Before adding any geometric value to a contract, look for its token first; if none exists, mint from-dump the way the Button's spacing was minted, and never hand-write the number. *(Spec 013 itself must NOT do this conversion — SC-005 forbids it on purpose and parks it in the `deferredWork` register; naming it is 013's job, doing it is another spec's.)*
- **The multi-writer bridge rule (§XI) — the figma-console bridge DOES accept several concurrent writers over several ports.** Partition the work into DISJOINT zones (different masters/pages/nodes) so no two writers ever touch the same node, and keep exactly one global pixel-verification cycle (before/after ×9) around the whole parallel batch, owned by the orchestrator, never by the agents. *Stated in full as constitution §XI.*

Canonical law: `.specify/memory/constitution.md` — on conflict, it wins. Source-cleanliness is §VIII there, docs-first is §IX, before-capture is §X, multi-writer bridge is §XI — all summarized above and stated in full in the constitution.

## Commands

```bash
npm install                # Node >= 20 required
npm run build              # tokens -> schema -> generate components (validated against contracts)
npm run dashboard          # Contract Hub app -> http://localhost:5180
npm run storybook          # the generated React library
npm run playground         # the browser playground (imports core/ unmodified)
```

**The gates — every change must leave all of these green** (canonical list: constitution §Quality Gates):

```bash
npm run build                                        # tokens → schema → components, contract-validated
npm run parity                                       # three-way differ: code, canvas, tokens vs contracts
npm run eval                                         # the deterministic suite — prints the live N/N
npm run plugin:check                                 # window.DSC anatomy; specHash mirror; drift refusal
npx tsx scripts/deterministic-roundtrip.mjs          # contract→canvas byte-identical ×2 (needs tsx: imports core/*.ts via .js specifiers)
node scripts/core-browser-check.mjs                  # core/ barrel bundles browser-pure
npx tsc --noEmit && npx tsc -p tsconfig.build.json   # types across src, scripts, core, extract, parity, evals
```

Notes:

- `npm run eval` prints the live `N/N` — that output is the only authoritative count; never hardcode it in prose (dated logs like `MILESTONES.md` are the exception).
- Feature specs run in git worktrees: make the worktree self-sufficient first (`npm install` + `npx playwright install chromium` inside it), then the FULL sweep — including `npm run eval` — runs there (constitution: Worktree Gates, F1). The runner symlinks *the checkout's own* `node_modules` into its scratch dir, which is exactly why a bare worktree fails it.
- Two checks (one eval + the visual-parity instrument) drive real Chromium; if missing, the error names the fix (`npx playwright install chromium` or set `PLAYWRIGHT_CHROMIUM_PATH`).
- Targeted checks (there is **no single-eval filter flag**): `npm run emitters:check`, `npm run mint:check`, `npm run mint:code:check`, `npm run extract:figma:*:check` (dialog, composite, tooltip, theme, repeat, …), `npm run parity`.

## Architecture

Flow is **outward from the contract to both surfaces, and back in as promotions** — surfaces never sync side-to-side. An engineer's new prop and a designer's color change take the same path: flagged by the differ → promoted into the contract as a reviewable diff → regenerated to the other surface.

- **`contracts/*.contract.json`** — the source of truth. A `Contract` (Zod-validated) has `id, name, version, props, anatomy, tokens, states, semantics, a11y, figma, modes, …`. Key concepts: `anatomy` is a `Record<string, Part>` so a component can be **multi-root**; props carry **dual bindings** (`bindings.figma` VARIANT/TEXT/BOOLEAN/INSTANCE_SWAP + `bindings.code`); composition via `component` (nested instance), `repeat + component` (collection), and `slot + accepts` (INSTANCE_SWAP slot). `contracts/icons.registry.json` governs the icon set (registry ↔ code ↔ Figma, verified by a parity icons axis).
- **`core/`** — the **engine as a pure browser-safe library**: zero `node:*` imports (receipted by `core-browser-check.mjs`); `core/index.ts` is the barrel — contracts go in as **data** (objects/maps, never paths), strings come out. Emitters (`core/emitter.ts` + `core/emit-*.ts`) form a pluggable registry with four built-ins: `react` (the shipping generator, byte-guarded by `evals/golden.json`), `html`, `react-inline`, `figma-script`; `registerEmitter()` opens the registry to plugins; `validateContract` (in `emit-react.ts`) is the shared **refusal gate** — invalid contracts fail *by name*. `emit-figma-script.ts` (`createFigmaEngine`) splits a small deterministic per-component spec from a large shared runtime interpreter. Extractors do code→contract (`propose-code.ts`, `extract-react-tsx.ts`, `extract-css-module.ts`) and canvas→contract (`propose-figma.ts`); unmapped observed values mint provisional `imported.*` tokens (`mint-tokens.ts` / `mint-code.ts`) — never invented, always reported.
- **`packages/`** — npm workspaces: `schema/` (`@ds-contracts/schema`, the **single live Zod document** at `packages/schema/src/contract-schema.ts`; `scripts/contract-schema.ts` is a re-export shim), `cli/` (`@ds-contracts/cli`, bin `ds-contracts`: `init, extract, generate, figma, diff, propose-pr`), `emitter-web-components/` (plugin-emitter example).
- **`figma-sync/`** — generated transport-agnostic canvas scripts + the **Sync Runner plugin**. The engine barrel is bundled into `window.DSC` (browser-pure IIFE, pure compute — contract text in, reports + script text out, never touches the `figma` global); `code.js` executes the scripts.
- **`scripts/plugin-engine-mock-figma.mjs`** — a faithful mock of the Figma Plugin API (Node VM, no Figma/network). Its fidelity is **load-bearing and imperfect**. **Mock-fidelity discipline:** a bug that only appears on the live canvas gets a two-part fix — (1) fix the emitter, (2) teach the mock to catch that class headlessly forever.
- **`parity/`** — the three-way differ (classifies every contract/code/canvas difference as ahead/behind/mismatched with a proposed remedy), the adherence judge, and the brownfield `diagnose` referee.
- **`tokens/`** — the Piqueray DTCG foundation (single brand, single mode): primitives → semantic aliases → modes. One pipeline (`scripts/build-tokens.mjs`) compiles to CSS custom properties *and* Figma variable collections. Contracts bind parts by `{dot.path}`; a binding to a nonexistent token fails the build.
- **`evals/`** — `run.ts` copies a scratch workspace, runs the **real** pipeline, applies one mutation, asserts exact behavior, byte-compares against `golden.json`, writes `results.json`. Families: C1 determinism, C2 refusal, C3 detection, C4 convergence, C5 extraction, C6 theming, C7 cli, C8 journey. Removed demo-era cases are named in `evals/REMOVED-CASES.md`; quarantined cases await Piqueray features (slots, composites, dark theme, a second brand).

## What to edit — and what is generated (never hand-edit)

| Change | Where |
|---|---|
| Component API / anatomy / token bindings / events | `contracts/*.contract.json` → then `npm run build` |
| Design tokens (incl. adding a brand) | `tokens/*.tokens.json` |
| Schema capabilities | `packages/schema/src/contract-schema.ts` — **add optional fields only, never repurpose**; bump `docs/02-contract-spec.md` |
| Generator behavior | `scripts/generate-components.ts`, `scripts/generate-figma.ts`, `core/emit-*.ts` |
| Extraction / brownfield | `extract/`, `core/propose-*.ts`, `core/extract-*.ts` |
| **Generated — NEVER by hand** | `src/components/`, `figma-sync/*.js`, `catalog/catalog.json`, `contracts/contract.schema.json` |

Hand-editing generated output *is* drift — the differ will flag it. That is the product working, not a bug to route around. Contract semver: added optional prop = minor; removed/renamed prop or value = major; widening a slot's `accepts` = minor, narrowing = major. The PR diff of a contract *is* the design-system change review.

## Honesty conventions

Degradation is named, never silent. Extraction marks every heuristic (`confidence: "inferred"`) and reports everything it can see but not read — silent omission is the highest-severity bug class here. If a check is skipped, the output must say so. Limits are documented where the capability is claimed, not in a footnote elsewhere.
